= Workflow Clean-Room Plan

NOTE: Superseded by link:orchestrator-refactor-plan.adoc[].

:status: complete
:supersedes: factory-module-refactoring-plan.adoc, factory-reduction-plan.adoc

This plan supersedes link:factory-module-refactoring-plan.adoc[] and link:factory-reduction-plan.adoc[].
The previous refactor extracted stage *interfaces* but left all stage behavior in
`factory.Service` through a `Publisher` callback. This plan gives the behavior to the stages.

== Principle

All four stages follow one uniform pattern: a small exported interface plus `New(Deps)`,
with every lifecycle, prompt, validation, and transition detail unexported.

Every stage is a deep module. `factory` is a control plane. `pipeline` is pure ordering
and outcome. No stage calls back into `factory`, and no transition is owned by the
orchestrator.

== Target architecture

[source,text]
----
factory  (control plane: CRUD, controls, messages, workers)
  └── pipeline.Run(ctx, taskID) -> Result
        ├── planner.Plan(Input)                              -> PlanResult{Approved}
        ├── builder.Build(Input, PlanResult)                 -> BuildResult
        ├── verifier.Verify(Input, PlanResult, BuildResult)  -> VerificationResult{Passed}
        └── reviewer.Review(Input, PlanResult, BuildResult, VerificationResult) -> ReviewResult{Approved}
----

`pipeline` has no store, lock, checkpoint, or transitions. Each stage returns a result;
`pipeline` reads the flags and derives `Outcome`. Cancellation is the only cross-cutting
concern.

`Planning`, `AwaitingApproval`, `Building`, `Checking`, `Reviewing`, and `Completed` are
set inside the owning stage, never outside it.

== Ownership

[cols="1,4",options="header"]
|===
|Module |Owns

|`factory`
|Task/session CRUD, delete/diff, approve/pause/abort/resume/retry, message and
intervention intake plus target resolution, worker registry, cancellation, shutdown,
projections. Invokes `pipeline.Run`.

|`pipeline`
|Fixed stage order, typed handoffs, outcome derivation from result flags, cancellation
guard. Nothing durable.

|`stage`
|Leaf value types shared by stages and pipeline (`Input`, result types). No store, git,
or workspace imports.

|`stagekit`
|Stage-only support: phase lifecycle and transitions, task lock, message drain,
config provider, lineage eligibility, artifacts/reports, evidence persistence, event
sink. Imported by stages (and composed by `factory`); never used to implement stage
logic.

|`planner` / `builder` / `verifier` / `reviewer`
|Their own `saved`/`begin`/`publish`/`fail` lifecycle and state transitions, prompts,
validation, evidence, read-only enforcement.

|`agentexec` / `workspace`
|Turn execution plus continuation; snapshots, fingerprint, profile, changed-files.
|===

Dependency arrow:

[source,text]
----
factory ──▶ pipeline ──▶ planner/builder/verifier/reviewer ──▶ stagekit ──▶ store/git/workspace/agentexec
                                   │                                 │
                                   └──────────────▶ stage ◀──────────┘
----

No cycles, no callbacks. `factory` imports stage packages and `stagekit` only to compose
them.

== Small interface per stage

Each stage exposes exactly one interface and one constructor. Everything else is
unexported.

[source,go]
----

}

func New(deps Deps) Service

`Deps` is the only other export per package. `Publisher` is deleted.

== Hidden lifecycle per stage

Every stage implements the same four unexported lifecycle methods with its own
transition.

[source,go]
----
// internal/planner/lifecycle.go (unexported)
func (s service) savedPlan(ctx, taskID) (stage.PlanResult, bool, error)
func (s service) beginPlan(ctx, taskID) (store.Task, store.Phase, error)          // Preparing -> Planning
func (s service) publishPlan(ctx, task, phase, payload) (stage.PlanResult, error) // Planning -> AwaitingApproval
func (s service) failPlan(ctx, phase, cause)
----

[cols="1,2,2",options="header"]
|===
|Stage |Begin transition |Publish transition

|planner
|`Preparing -> Planning`
|`Planning -> AwaitingApproval` (on approved resume, stage reports `Approved=true`)

|builder
|`-> Building`
|`Building -> Checking`

|verifier
|`-> Checking`
|`Checking -> Reviewing`

|reviewer
|`-> Reviewing`
|`Reviewing -> Completed`
|===

Stage-specific hidden behavior:

* `planner`: read-only repository fingerprint enforcement, plan approval digest.
* `builder`: protected-path enforcement, test-evidence persistence.
* `verifier`: check and comparison execution plus report rendering.
* `reviewer`: upstream evidence assembly, verdict validation, read-only enforcement.

== Pure pipeline

[source,go]
----
func New(p planner.Service, b builder.Service, v verifier.Service, r reviewer.Service) *Pipeline

func (p *Pipeline) Run(ctx context.Context, taskID string) (Result, error) {
    input := stage.Input{TaskID: taskID}

    plan, err := p.planner.Plan(ctx, input)
    if err != nil {
        return Result{}, err
    }
    if !plan.Approved {
        return Result{Outcome: Waiting, Plan: plan}, nil
    }

    build, err := p.builder.Build(ctx, input, plan)
    if err != nil {
        return Result{Plan: plan}, err
    }

    verification, err := p.verifier.Verify(ctx, input, plan, build)
    if err != nil {
        return Result{Plan: plan, Build: build}, err
    }
    if !verification.Passed {
        return Result{Outcome: Blocked, Plan: plan, Build: build, Verification: verification}, nil
    }

    review, err := p.reviewer.Review(ctx, input, plan, build, verification)
    if err != nil {
        return Result{Plan: plan, Build: build, Verification: verification}, err
    }
    if !review.Approved {
        return Result{Outcome: Blocked, Plan: plan, Build: build, Verification: verification, Review: review}, nil
    }
    return Result{Outcome: Completed, Plan: plan, Build: build, Verification: verification, Review: review}, nil
}
----

`ctx.Err()` guards remain around each call and before the success return so a cancelled
run cannot publish late success.

== stagekit responsibilities

* `Journal`: `Begin`, `Complete`, `CompletePlanner`, `CompleteVerification`, `Fail`,
  `Reuse`, `EnsureDefinition`, `Artifact`.
* `Locker`: task lock registry. Stages lock only for begin and drain-publish, never
  during agent execution.
* `Drain`: initial turn plus queued-message continuation loop, parameterized by the
  stage's validator, continuation prompt, and read-only flag.
* `ConfigProvider`: per-task config and `TaskDir` for prompt rendering and sessions.
* `Lineage`: `SuccessfulPhase`, `RequireAttempt`, `EligibleAfter`, `PhaseEnvelope`.
* `Sink`: event and trace sink factory.

== Factory slim surface

`factory` keeps `root`, `db`, `config`, `configPath`, `harnesses`, `git`, `sandbox`,
`mu`, `cancel`, `taskLocks`, and `workflow`. It provides `Create`, `CreateSession`,
`Delete`, `Diff`, `Approve`, `Pause`, `Abort`, `Resume`, `Retry`, `SendMessage`,
`Intervene`, and `Shutdown`, plus the worker registry. `progress` calls `pipeline.Run`.

Deleted from `factory`: `Pipeliner`, `NewPipeline func(*Service)`, `SetPipeliner`, all
`Saved*`/`Begin*`/`Publish*`/`Fail*` bridge methods, `stage_backend.go`, stage machinery
in `factory/pipeline.go`, `drainMessages`, `runRetryAttempt`, `stateForPhase`,
`stateForRole`, and the `Publisher` interfaces.

`Resume` no longer computes a target state; it validates eligibility and relaunches
`pipeline.Run`, and the stage transitions itself on `begin`.

== Implementation sequence

. Create `internal/stage` value types and `internal/stagekit` primitives extracted from
  `factory`.
. Move continuation into `stagekit.Drain` backed by `agentexec`.
. Port `planner` to own its lifecycle; delete its `Publisher` and bridge.
. Port `builder`, then `verifier`, then `reviewer`, deleting each bridge and `Publisher`.
. Rewrite `internal/pipeline` to the pure `Run`.
. Rewire `factory.progress`; delete stage machinery; compose
  `pipeline.New(planner.New(...), builder.New(...), verifier.New(...), reviewer.New(...))`
  in `main.go`.
. Keep config `Pipelines` as kind-to-agent and stage-ID presets; order stays fixed in
  `pipeline`.
. Rewrite tests against `pipeline.Run` and the stage interfaces.

== Verification

[source,text]
----
go -C daemon test ./...
go -C daemon test -race ./...
npm run typecheck
npm run build
----

Behavioral contracts:

* Approval yield and resume without replanning.
* Verify failure stops downstream execution.
* Verify-only retry reuses the selected plan and build.
* Upstream change invalidates downstream results.
* Message arriving during completion drains, then publishes.
* Cancellation prevents late successful publication.
* Read-only enforcement for planner and reviewer.
* Protected-path enforcement for builder.
* Retry idempotency with the original input snapshot.
