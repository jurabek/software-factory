= Orchestrator Extraction Plan

:supersedes: workflow-clean-room-plan.adoc (completes its Factory surface)

The clean-room refactor moved stage behavior out of `factory` but left control-plane
adjacent logic inside it: config/pipeline resolution, projections, anchor/target
handling, retry/intervention materialization, messaging recipient/session bootstrap,
and task file creation. This plan extracts those and renames `factory` to
`orchestrator`.

== Principle

`orchestrator` owns identity, lifecycle, synchronization, and the hand-off to
`pipeline`. It contains no workflow, config, filesystem-layout, anchor, recipient,
or retry mechanics. Each extracted module is a deep module: one small surface,
Deps plus New, everything else unexported.

== Ownership

[cols="1,4",options="header"]
|===
|Module |Owns

|`orchestrator`
|`New`, `Create`/`CreateSession`/`Delete`/`Diff` delegation, `Approve`/`Pause`/`Abort`/`Resume`,
`SendMessage`/`Intervene`/`Retry` intake, task lock registry, worker registry,
cancellation, shutdown, `progress` -> `pipeline.Run`.

|`task`
|Task identity, filesystem layout, metadata file, repository normalization, config
snapshot at creation, session (child task) creation, branch ensure, delete, diff.
Exposes `Create`, `CreateSession`, `Delete`, `Diff`; owns `CreateRequest`,
`CreateSessionRequest`, `Repository`, `Diff`.

|`projection`
|`StageProjection` read model over phases + task pipeline.

|`intervention`
|Anchor validation, target resolution, intent policy (`ValidateIntent`), retry/revise/
repair attempt + branch + definition materialization, `Retry`. Owns `Anchor`,
`Target`, `Request`, `RetryRequest`, `ErrInvalidFeedback`.

|`messaging`
|Message intake, recipient resolution, agent-session bootstrap, message event
persistence, queued-message continuation. Owns `Request`.

|`config`
|Gains `Freeze`, `SelectPipeline`, `TaskPipeline`, `Snapshot`, `Resolve` (moved from
`factory` and `stagekit`).

|`stagekit`
|Delegates config resolution to `config`; keeps stage support and `AvailableActions`.
|===

== File-by-file sequence

. `config`: add `Freeze`, `SelectPipeline`, `TaskPipeline`, `Snapshot`, `Resolve`,
  `Fallback`; tests.
. `stagekit`: `TaskConfig`/`ResolveConfig`/`TaskPipeline`/`FallbackPipeline` delegate
  to `config`; delete duplicated bodies.
. `task`: move from `factory/service.go` (`create`, `CreateSession`, `Delete`, `Diff`,
  `normalizeRepository`, `taskID`, `snapshotConfig`, `ensureBranch`) and the
  `Create*`/`Repository`/`Diff` types; tests move here.
. `projection`: move `StageProjection`/`stageDefinition` from `factory/pipeline.go`.
. `intervention`: move `intervene.go`, anchor/target/policy, and `Retry` from
  `factory/message.go`; tests move here.
. `messaging`: move `SendMessage`, `messageRecipient`, `ensureAgentSession`,
  `MessageTarget` from `factory/message.go`; tests move here.
. `orchestrator`: rename package/dir; `service.go` keeps deps, controls, worker
  registry, `progress`; `message.go`/`intervene.go` become thin delegations; delete
  `factory/pipeline.go`, `factory/policy.go`; `state.go` aliases stay.
. `api` + `main.go`: update imports and `taskFactory` signatures to the new DTO
  packages; `main.go` composes `orchestrator`.
. `docs`: mark `workflow-clean-room-plan.adoc` superseded.

== Verification

[source,text]
----
go -C daemon build ./...
go -C daemon test ./...
go -C daemon test -race ./...
npm run typecheck
npm run build
----

Behavioral contracts unchanged: approval resume without replanning, verify failure
stops downstream, verify-only retry reuses plan/build, upstream invalidation, message
drain before publish, cancellation prevents late success, retry idempotency.

== Unresolved questions

* Keep `factory` compat aliases or hard rename all callers? (plan: hard rename)
* `task` lock vs `stagekit` lock remain separate mutexes? (pre-existing; out of scope)
* `Intervene` has no HTTP route; keep method or delete? (plan: keep, tests only)
